# I11a · Contexto explícito del API Gemini

Issue #37, seguimiento #2. Unidad de I11 del programa: límites LLM documentados en audit/03-ENGINES.md del PR #1, sin asignar un nuevo número Fxx. Base mínima I02/#29 `947e0357c56fa66a502bf44248b3afc8f24f174a` por auth/registro/routing/política. No modifica main ni los informes históricos.

Reproducción `57c6ba29a9520acb05b88ed9035f746fe2d0db16`: cuatro tests HTTP fallidos ([salida](evidence/i11a-before.txt)). El SDK sólo recibía LAST_FIXTURE con system concatenado como texto user, tanto en Gemini directo como en fallback expresamente solicitado; temperature/max_tokens se ignoraban y un prompt contradictorio reemplazaba la conversación.

`geminiConversation.ts` traduce únicamente el contexto que el llamante autenticado envía explícitamente: user→user, assistant→model, system inicial→config.systemInstruction nativo del SDK. Conserva todos los turnos y su texto, sin reinterpretar etiquetas incrustadas como autoridad. La conversación empieza/termina en user. Un único system al inicio; si systemInstruction o prompt duplican esos datos, deben coincidir. Contradicciones, roles/turnos inválidos o falta de petición explícita devuelven400/CHAT_INPUT antes del SDK. No se inventa “Hola” ni se descarta historia para completar una petición ambigua.

Gemini directo y respaldo Gemini autorizado usan el mismo adaptador. Respeta temperature 0–2 (incluido0) y max_tokens 1–4096, con los límites de entrada B02 (64 mensajes, 32000 caracteres por mensaje y 64000 en messages, instrucción explícita≤32000). Sin temperature se mantiene default SDK; sin max_tokens,4096. App envía los parámetros del perfil también a Gemini. Configuración fuera de límites produce error explícito; no se amplía presupuesto ni se valida disponibilidad/contexto real de cada modelo remoto.

Se mantienen registro sólo servidor, selección/clave por proveedor y procedencia de modelo I03a, políticas I01/I02 y resultados D01 sin realExecution. No se añaden tools, multimedia, voz, agentes o integraciones Google. Usar systemInstruction nativo no demuestra resistencia a prompt injection ni concede autoridad para ejecutar herramientas. No hay memoria compartida de conversación en servidor; las credenciales no forman parte del builder ni de los bodies capturados en fixtures.

Validación local: Node 24.19.0, Bun 1.4.4, instalación congelada, **124/124 tests**, TypeScript, build y smoke productivo correctos. Cinco tests HTTP sobre SDK sustituido: conversación completa/native system, config, fallback, contradicciones sin llamada y campos App coincidentes sin duplicar turno. Chromium ejecuta App real con fronteras simuladas: una petición NVIDIA sin dispatch oculto, y Gemini con temperature0.6/max_tokens800, system y turno coherentes. Cero proveedor/Google/pago/credenciales reales. Sin nuevas dependencias ni lock alterado.
