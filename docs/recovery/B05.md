# B05 · Propiedad y audiencia Web Push

Issue #20, seguimiento #2, F04/N04. Base D03 (#19, `6aeca68a9ab45ed9c936f2550510b6134bd57070`). Regresión previa `11c073502fb76743a0336b7094171a3ffbf372fc`: cuatro subpruebas HTTP fallidas con dos JWT RS256 de ensayo. B podía contar, enviar a, reclamar y borrar la suscripción de A. [Salida](evidence/b05-before.txt). El sender antiguo se interceptó mediante preload; cero envíos externos.

El registro ahora guarda el UID del token verificado, no el de la petición. Status/subscribe/unsubscribe/dispatch se limitan al propietario; reclamar un endpoint de otra cuenta devuelve 409 y borrarlo devuelve el mismo 404 que uno ausente. La programación captura el UID autenticado y vuelve a comprobar los registros vigentes al ejecutarse. Una respuesta tardía 410 no puede borrar un registro reemplazado. No hay broadcast ni audiencia arbitraria por body.

Sólo endpoints HTTPS:443 de hosts exactos administrados en servidor. Defaults: `fcm.googleapis.com`, `updates.push.services.mozilla.com`, `web.push.apple.com`; `PUSH_ADDITIONAL_HOSTS_JSON` añade hasta 32 hostnames exactos (p. ej. el hostname concreto que use un navegador corporativo). Sin comodines, puertos alternativos, IP literales ni excepciones locales. Se validan curva P-256, auth de 16 bytes, base64url canónico y expiración. Se preservan queries de tokens de los servicios push; credenciales URL y fragmentos se rechazan. Un host permitido sigue sujeto al control de **todas** las IP resueltas.

`web-push` genera localmente el ciphertext aes128gcm y la firma VAPID; su sender HTTP sin restricciones deja de usarse. El transporte binario común conserva DNS fijado, peer/puerto, SNI, certificado TLS y rechazo de redirecciones de F01. Sólo cabeceras Web Push generadas en servidor, sin Host/Cookie/proxy/CRLF. No hay reintento después de transmitir. Los errores no exponen endpoints, claves ni respuestas de proveedor.

Límites por proceso: cinco dispositivos por UID/10.000 globales, dos despachos activos por UID/ocho globales, diez programaciones por UID/100 globales y retraso de hasta 24h. Payload UTF-8 de hasta 3.000 bytes; navegación/iconos/badges sólo rutas de la aplicación. Cada dispositivo usa deadline 15s; las concesiones de programación se retienen mientras se ejecuta el callback. El 202 identifica `not_attempted`, `durable:false`; `sent` sólo cuenta aceptación HTTP 2xx del servicio, con `delivery:service_acceptance_only`. No se promete recepción/visualización del dispositivo.

El cliente comprueba el HTTP de registro, serializa cambios de identidad y revoca la credencial del navegador al cambiar UID/cerrar sesión, incluida una suscripción antigua sin propietario local verificable. Sólo escribe la marca de UID después del registro aceptado y de comprobar otra vez la identidad. Cierra notificaciones ya mostradas por esa inscripción al revocar. Se intenta borrar el registro de servidor antes de signOut, con timeout; el unsubscribe local se intenta también si el servidor falla. No se migran ni asignan historiales, API keys o bóvedas antiguas.

Validación: 125 tests (HTTP con dos usuarios, registros/reemplazos, programación/cupos, cambio de identidad, errores de registro, destinos/DNS, ciphertext real generado localmente y transporte binario de fixture), TypeScript, build, smoke productivo y regresión Chromium de privacidad. Node 24.19.0, Bun 1.4.4 e instalación congelada, sin cambios del lock. Sin permisos de dispositivo, push real, Google real ni pagos. CI/SHA remoto y revisión se enlazan en PR/#2.

Límites residuales: registro, VAPID generado sin env y programaciones siguen siendo volátiles por proceso; se pierden al reiniciar y los cupos no son distribuidos. No se puede retirar una petición ya transmitida ni un push ya aceptado por el servicio. Si el navegador falla al revocar, se registra advertencia y debe revocarse su permiso; no se afirma logout como prueba de entrega/cancelación remota. Timers locales del SW y scheduler durable siguen en I09/K15; aislamiento de otros datos del navegador sigue en B04. La compatibilidad real de dispositivos/proveedores requiere fixtures o cuentas explícitamente autorizados. No se declara auditoría independiente ni integración.
