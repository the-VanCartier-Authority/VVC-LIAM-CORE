Su CI [40418188153](https://github.com/the-VanCartier-Authority/VVC-LIAM-CORE/actions/runs/40418188153), job 121905662298, terminó **SUCCESS sobre ese SHA exacto**, con instalación congelada, 81/81 Node, Chromium 156.0.8078.4 (una fixture/cinco casos), tipos, build, smoke y lock correctos. Ese resultado no cubría la fuga posterior a una salida normal con hijo desacoplado: Manus la reprodujo y emitió **CAMBIOS NECESARIOS**, según el dictamen comunicado por el propietario. CI exitosa no equivale a ausencia de defectos ni aprobación independiente.

La nueva regresión reproduce exactamente el defecto sobre `897d3c9…`: fixture que crea un hijo desacoplado sin pipes de salida heredados, abre un puerto local y termina con código 0. El runner devolvía PASS con el hijo vivo, reparentado a PID 1, y `EADDRINUSE`. La prueba conserva ese diagnóstico y su rescate limpia el recurso tras el fallo. Ahora exige hijo terminado/recogido, puerto reutilizable y confirmación de limpieza antes del PASS. Se mantienen los cinco casos anteriores y se añade otra regresión: un supervisor que sale 0 sin evidencia de limpieza debe fallar sin ejecutar fixtures. **Suite vigente: 83 pruebas Node (81 anteriores más dos nuevas)**. El navegador sigue siendo un gate separado (`npm run test:browser`): una fixture con cinco casos Chromium, no incluidos en `npm test`.

El runner usa un supervisor Linux por fixture, iniciado con `python3 -I` y sólo biblioteca estándar; la fixture continúa ejecutándose con Node 24.19.0. **Requisitos explícitos:** Python 3 con `os.pidfd_open` y `signal.pidfd_send_signal`, kernel con `PR_SET_CHILD_SUBREAPER`/pidfd, libc y `/proc` accesible. Se verifican antes de iniciar la fixture; si faltan, el gate falla, sin fallback que pueda declarar PASS. Python local 3.12.14; la versión efectiva del supervisor se registra también en el gate de CI. El workflow sigue en Ubuntu 24.04; no se incorporan paquetes npm/Bun ni se cambia el lock. Windows/macOS no están soportados por esta supervisión y fallan explícitamente.

`PR_SET_CHILD_SUBREAPER` adopta los huérfanos antes de perder la relación con el kernel; no se intenta deducir su pertenencia recorriendo únicamente el árbol del padre ya terminado. Los hijos adoptados se enumeran bajo el supervisor vivo. Antes de señalizar se abre un **pidfd**, se verifica PPID y sólo se recogen hijos con `waitpid`; las señales usan ese descriptor estable para evitar terminar un PID reutilizado. Cada hijo recibe SIGTERM y, tras 500 ms, SIGKILL. La salida normal también inicia limpieza. El plazo de ejecución sigue siendo 120 s por fixture; la limpieza tiene un presupuesto separado de 3 s y se espera la salida del supervisor. SIGINT/SIGTERM cancelan sin PASS, con códigos 130/143. Timers y handlers del runner se eliminan al cerrar cada fixture.

Para declarar PASS se requieren salida 0 de fixture y supervisor, ausencia de errores y una evidencia privada del supervisor que confirme **`waitpid(ECHILD)` y cero hijos pendientes**. La fixture no hereda el canal de esa evidencia. Si no se puede verificar, se devuelve `BROWSER_FIXTURE_CLEANUP_FAILED`; enviar una señal o recibir un código 0 por sí solos no acreditan limpieza. Las pruebas de timeout acortan únicamente la constante del plazo en una copia temporal; el watchdog externo del test es rescate y nunca cuenta como limpieza correcta del runner.

**Límites:** esto supervisa fixtures de confianza bajo el mismo kernel/espacio de PID, no constituye un sandbox para procesos hostiles. Un SIGKILL del propio supervisor, escape de su supervisión mediante privilegios/namespaces, manipulación del runner/entorno o procesos no terminables por el sistema operativo pueden impedir la limpieza. El guard exterior invalida el resultado si el supervisor se bloquea o pierde la prueba de cierre; no garantiza entonces la eliminación de procesos escapados. Si vence el presupuesto de limpieza se registra fallo, nunca PASS, y se requiere intervención del supervisor del job/cgroup. No se atribuye garantía absoluta ni soporte multiplataforma no probado.

Cada SHA nuevo requiere instalación limpia congelada, runtime, suite completa y focalizada, Chromium explícito, TypeScript, build y smoke productivo. El head y la CI exactos de esta corrección se registran en #7/#2; **40418188153 sólo acredita 897d3c9…**, no el head posterior. Las pruebas usan únicamente recursos locales sintéticos y bloquean el tráfico externo del producto. No se solicita otra auditoría general; queda pendiente la comprobación independiente incremental de esta corrección.
