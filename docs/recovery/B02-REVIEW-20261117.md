## Reproducciones de caracterización

Se ejecutaron dos comprobaciones locales de módulo con Node `v24.22.1`, sin proveedores ni credenciales reales. No sustituyen la suite del runtime fijado por el proyecto.

1. Middleware HTTP con un UID y un cupo. Se capturó el callback del temporizador sin esperar 120 s. Una segunda concesión se rechazó antes del callback. Tras invocarlo, el mismo UID obtuvo otra concesión sin haber emitido evento de fin ni completado trabajo de proveedor. Resultado: `slotReusableAfterDeadline=true`, `providerCompletionObserved=false`.
2. Validador de payload con `/CHAT/gemini` y presupuesto de 4096. La ruta literal no consumió reserva y una reserva posterior completa fue aceptada. Esto demuestra la diferencia entre comparaciones literales; la aceptación HTTP de esa variante debe verificarse antes de clasificarla como bypass confirmado.

Los ocho blobs sin conflicto se compararon con el head original. El main nuevo sólo añade auditor Gemini respecto de la base anterior `d030024e60e35e49a14e6c6beccbb730c7646c60`. No se incorporaron cambios de otros grupos funcionales.

## Cuotas por proceso y varias instancias

- Cada proceso tiene sus propios contadores por UID y sus límites globales. Con N procesos, un usuario puede encontrar capacidad en varios procesos. No se afirma una cuota única del servicio.
- Un reinicio elimina reservas, ventanas de rate limit y estado de tareas en RAM. Concesiones existentes no se reconstruyen desde almacenamiento durable.
- La reserva de `4096 × intentos` es una política conservadora. No representa consumo medido, tokens facturados ni un límite financiero global.
- La afinidad de sesiones no demuestra consistencia durante reinicios, reintentos o balanceo. Una solución distribuida o durable requiere diseño y autorización propios.
- El middleware actúa después de verificar identidad. La protección de conexiones, CPU y volumen anterior a autenticar depende de una infraestructura aún no acreditada.
