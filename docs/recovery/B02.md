# B02 · Límites de recursos

Issue #12, seguimiento #2. Base B03 (#11, `6f94b7c61cf45536fd99cbecc8bed5ffcb8fa7af`) proporciona ownerUid de tareas; B01 aporta identidad. Rama `fix/p0-b02-resource-limits`. Reproducción antes: commit `994dec1`, dos regresiones HTTP fallan por ausencia de rate limit y límite de tokens. [Salida](evidence/b02-before.txt).

Política propuesta, administrada en servidor mediante BACKEND_LIMITS_JSON: 120 solicitudes/minuto por UID; 4 HTTP concurrentes/usuario y 64 globales; 2 tareas VAOS/usuario y 8 globales; 1.000.000 tokens de **reserva conservadora** por UID/día UTC. Campos desconocidos, valores no enteros/positivos o fuera del rango de configuración impiden arrancar. El cliente no puede cambiar la política.

Cada generación está limitada a 4096 tokens de salida; reserva hasta tres intentos para NVIDIA/VAOS, uno para Gemini/test y cinco para TTS. Son máximos reservados, no tokens medidos ni facturación. Una petición fallida conserva su reserva para impedir abuso de reintentos. Los SDK tienen timeout y un solo intento interno; los fallbacks explícitos conservan el límite. Los topes administrativos son revisables antes de integrar/desplegar.

JSON máximo 256 KiB; hasta 64 mensajes de texto, 32.000 caracteres por mensaje y 64.000 totales; prompt/system de 32.000; comandos 5.000; TTS 8.000; max_tokens entero 1–4096 y temperature 0–2. Roles soportados por este cliente: system/user/assistant. No se añade una API multimodal/herramientas que el producto no implementa. Los errores son 400/413/429/503, con Retry-After cuando procede y sin cuerpos/secretos reflejados.

Las concesiones HTTP se liberan al terminar; una desconexión temprana conserva la concesión hasta su plazo de 120 s para no eludir concurrencia mientras sigue el proveedor. VAOS conserva su concesión después de responder al dispatch y la libera al terminar, también en fallo/no disponible. No se eliminan tareas activas por retención: historial RAM acotado a 100 terminales por usuario/1000 globales; no es persistencia I10. Los buckets de usuarios son acotados y se limpian con el día del servidor. Edge TTS incluye metadata/conexión en sus 7 s, cierra recursos y limita audio a 4 MiB.

Validación: instalación congelada, 101 tests incluyendo cuotas por UID, ventanas/renovación, concesiones idempotentes, HTTP concurrente real con proveedor local y concurrencia asíncrona tras dispatch. TypeScript, build y smoke locales. Ningún servicio de pago, Google real o credencial real. Los cambios no añaden capacidades de voz; sólo limitan recursos del transporte existente.

Límites: políticas **en memoria por proceso**. Reiniciar reinicia contadores; varios procesos no comparten presupuesto. No se declara cuota distribuida/durable ni defensa completa frente a DDoS previo a autenticar. El despliegue necesita coordinación/limitación en infraestructura antes de afirmar esas garantías. Push, estado local y bóveda siguen B04/B05/C01/C02. Revisión independiente, integración y pruebas con servicios reales pendientes; no habilita producción global.
