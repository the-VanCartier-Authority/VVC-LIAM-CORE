## Reproducción y cambios

Las 13 rutas sensibles aceptaban requests sin identidad o llegaban al handler sin verificarla. Regresión previa en `c471576`: 13 subtests y su test padre fallan; [salida](evidence/b01-before.txt). Esta reproducción se ejecutó tras acabar instalación, separando un fallo inicial de instalación incompleta de la reproducción válida del defecto.

Todo `/api` queda detrás del middleware antes de parsear JSON, con lista pública mínima de GET `/api/config`, `/api/push/vapid-public-key` y `/api/vaos/health`. Son configuración sin secretos, clave pública y estado básico; no tareas, contenido ni telemetría. Chat NVIDIA/Gemini/custom, test de secretos, TTS, dispatch/tareas/telemetría VAOS y estado/registro/borrado/envío push requieren Bearer válido. No se aceptan tokens por query o cookies ni header duplicado.

Se usa jose 6.2.13 fijado (una dependencia nueva, sin transitivas) para verificar criptografía JWT, sin implementar firmas a mano. El JWKS de Firebase está fijado a su URL Google HTTPS; ni request ni variable permiten reemplazarlo. Se comprueban RS256, kid, firma, issuer/audience del proyecto exacto, UID no vacío de hasta 128 caracteres, exp/iat/auth_time obligatorios y válidos, duración máxima 1 h. Claves desconocidas, rotación no confiable y fallos de descubrimiento se rechazan sin ejecutar handlers. La caché/plazos de JWKS son acotados. No se requiere clave privada Admin ni service account.

El proyecto esperado procede del entorno de servidor `FIREBASE_PROJECT_ID` o del projectId de firebase-applet-config.json. Si se cambia proyecto, el cliente también debe configurar el mismo; un proyecto diferente se rechaza. No se habilita ningún bypass de emulador.

El cliente pide `auth.currentUser.getIdToken()` en cada request, comprueba que no cambió el usuario mientras lo esperaba y sólo lo transmite al backend del mismo origen. Separa este ID token del access token OAuth Workspace. Se adaptan LLM, VAOS, TTS, test de claves y push. No se modifica UI ni se añade integración Google. No se guardan tokens nuevos en localStorage y no se permiten redirecciones de requests autenticados.

## Validación

Node 24.19.0 / Bun 1.4.4; instalación congelada del lock actualizado, 89/89 tests, TypeScript, build y smoke local pasan. Los tests firman JWT con RSA efímera y sustituyen sólo la respuesta pública JWKS en un preload de ensayo: el verificador de producción y su criptografía se ejecutan completos. Hay dos UID, dos claves de rotación, firmas alteradas, alg none, expirados, iat/auth_time futuros o ausentes, issuer/audience/proyecto incorrectos, claves desconocidas y fallo de JWKS. El helper autentica las regresiones anteriores para que F01 siga probándose después de superar auth.

Smoke: estáticos 200, identidad ausente 401, identidad firmada válida 200, rutas SSRF rechazadas tras auth y proveedor registrado aceptado. No hay JWT reales, cuentas, Google Workspace real, inferencia externa ni pago. El resultado remoto de CI se enlaza desde el PR y la checklist #2.
