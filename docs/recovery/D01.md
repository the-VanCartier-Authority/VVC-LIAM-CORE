Ni texto del modelo, ni un recibo enviado por el cliente, ni HTTP 200 sirven de evidencia de una acción de negocio. No se añade un verificador ficticio ni una herramienta nueva para producir true.

VAOS sólo completa generación de texto cuando existe una respuesta del proveedor; sin clave termina UNAVAILABLE y cuando fallan todos los candidatos termina FAILED. Los fallbacks LLM fallidos/vacíos devuelven errores, sin inventar un motor local. El cliente conserva LLM/RT Lite/agentes separados y muestra el fallo; no lo convierte en ejecución RT Lite. El RT Lite genérico tampoco declara ejecutada una petición que no reconoce. Las mediciones y afirmaciones de privacidad pendientes no se consideran cerradas: son D02/D03.

## Ampliación: recibos de webhook y estados locales

La revisión posterior detectó que `dispatchTaskWebhook` usaba no-cors y devolvía success/200 sin leer el resultado. Regresión previa `437097a5289d25fa9fbac390179486e3377d2ce0`: cuatro casos fallidos ([salida](evidence/d01-webhook-before.txt)): HTTP 403, respuesta opaca, 202 sustituido por 200 y fallo de red sin procedencia. Todas las respuestas fueron mocks, sin enviar eventos reales.

Ahora devuelve delivery accepted, failed, unverified o not_attempted; conserva el HTTP observado y realExecution siempre false. Sólo un 2xx legible permite accepted y no prueba la ejecución de la automatización remota. Una respuesta opaca/red/CORS/timeout/redirección sin recibo es unverified: puede haber llegado al servicio, sin afirmar entrega ni no-entrega. Se usa CORS, credentials omit, redirect error y deadline 15s. URL inválida/con credenciales se rechaza antes del envío. No se exponen cuerpos upstream, detalles de excepción o URLs secretas en el resultado.

El probador de UI distingue aceptación HTTP de ejecución y deja de imprimir Status 200 fijo. Nuevas tareas/eventos manuales parten sin marcas de sincronización completada; marcar una preferencia no constituye un recibo. El parser y otros flujos se corrigen en sus unidades (I07/I05), sin migrar ni atribuir propiedad a datos históricos.

Validación ampliada: 76/76 tests (cinco escenarios de webhook adicionales), TypeScript, build y smoke, Bun 1.4.4/Node 24.19.0/frozen lock. Sin cambios del lock, Google/webhooks reales, claves o pagos. Servicios sin CORS legible ya no aparentan funcionar mediante una respuesta opaca; no se añadió un relay ni una integración. La política de destinos/custodia y la prueba real de entrega permanecen separadas. CI depende de E01 aún no integrado; compatibilidad conjunta y SHA actuales se registran en #2.
