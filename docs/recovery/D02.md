# D02 · Procedencia de métricas

Issue #16, seguimiento #2, F27/N27. Base E02 (#15, `72be2a188bade2258ed80305dcc96ef8d1c265e5`). Antes de corregir: commit `4c08086`, tres regresiones fallidas: promedios sin muestras, TPS de plantillas locales y batería sintética sin API. [Salida](evidence/d02-before.txt).

La telemetría ahora identifica `tokensSource`: provider, estimated o unavailable, y `latencyScope`: policy_routing o processing_wall_time. El contador informado por el proveedor se conserva como tal; si no existe, caracteres/4 sólo se muestra como estimación de conteo, sin atribuir TPS. La tasa sólo se calcula con tokens reportados y tiempo monotónico real de procesamiento; **no** es TPS interno del modelo, latencia de voz ni SLA de extremo a extremo. Se retiran 64 TPS de boot, floors de tiempo artificiales y defaults de promedios sin muestras.

Sin datos, API/UI muestran null/N/D, contadores cero y gráficas vacías; no áreas mínimas ni estadísticas de ejemplo. El panel borra valores al fallar la lectura y no presenta generación fallida/no disponible o timeout de polling como benchmark completado. Los cambios visuales sólo aclaran esas métricas, sin modificar la organización de la interfaz ni branding.

Batería sólo usa valores válidos de la API del navegador. Sin API, nivel/carga/tiempos son desconocidos; se elimina el drenaje simulado y temperatura/"salud óptima" no medidos. La carga no se describe como carga rápida.

Validación: 108 tests, incluyendo estados vacíos, routing, generación con/sin usageMetadata y API de batería simulada; TypeScript, build y smoke. JWT/servicios mock de ensayo, cero llamadas reales Google/inferencia/pago. Revisión independiente, CI remota e integración se registran en PR/#2. No se afirma que las estimaciones sean mediciones ni que se haya certificado rendimiento del modelo/dispositivo.
