### Reproducción segura de F01/F02/F03/F10

1. HTTP local sin Authorization de aplicación: `/chat/nvidia` y `/chat/custom` alcanzaron un servidor mock en 127.0.0.1:3199 y devolvieron 200. Se usó `fixture-only`, nunca una credencial real.
2. Harness interceptó fetch con `NVIDIA_API_KEY` sintética en process.env: request de cliente sin clave y con endpoint loopback incluyó Bearer de servidor. Esto demuestra la composición vulnerable. No demuestra acceso a metadata cloud ni exfiltración real en producción.
3. HTTP anónimo obtuvo `/vaos/tasks` con comando/resultado de una tarea sintética ajena a la identidad del request; el código no modela identidades de propietario.
4. `formatear bóveda de prueba` con forcePriority P2 devolvió FAST_PATH aprobado, sin realizar formateo. El filtro `<script>` inicial se mantiene; no se afirma un bypass de ese filtro.

## Zero-Knowledge y criptografía

Existe criptografía real **sólo en la utilidad de bóveda**: PBKDF2/SHA-256 100.000 iteraciones, salt de 16 bytes, AES-GCM-256 con IV aleatorio de 12 bytes y CryptoKey no exportable. El harness confirmó roundtrip y rechazo con contraseña errónea. No se revisó mediante auditoría criptográfica formal ni se midió resistencia a contraseñas débiles. [src/utils/crypto.ts:28](https://github.com/the-VanCartier-Authority/VVC-LIAM-CORE/blob/2ffadf44c2c09bbc8dcde47046ee7d5c08a039f7/src/utils/crypto.ts#L28), [src/utils/crypto.ts:40](https://github.com/the-VanCartier-Authority/VVC-LIAM-CORE/blob/2ffadf44c2c09bbc8dcde47046ee7d5c08a039f7/src/utils/crypto.ts#L40), [src/utils/crypto.ts:67](https://github.com/the-VanCartier-Authority/VVC-LIAM-CORE/blob/2ffadf44c2c09bbc8dcde47046ee7d5c08a039f7/src/utils/crypto.ts#L67).

No se usa esa utilidad para API keys, chat, tareas, contactos ni Firestore. `isE2EE:true` se asigna a mensajes incluso cloud, pero prompts y respuestas están en claro para servidor/proveedor. TLS, cuando exista en despliegue, no hace que el servidor desconozca contenido. No existe E2EE para llamadas tel:, ni control criptográfico que respalde las afirmaciones de «encriptación de hardware». F05/F06 impiden respaldar Zero-Knowledge como propiedad del sistema. [src/App.tsx:1199](https://github.com/the-VanCartier-Authority/VVC-LIAM-CORE/blob/2ffadf44c2c09bbc8dcde47046ee7d5c08a039f7/src/App.tsx#L1199), [src/components/DeviceControlsDrawer.tsx:83](https://github.com/the-VanCartier-Authority/VVC-LIAM-CORE/blob/2ffadf44c2c09bbc8dcde47046ee7d5c08a039f7/src/components/DeviceControlsDrawer.tsx#L83).

La contraseña inicial de la bóveda está incorporada en el código; su valor se omite deliberadamente. El fingerprint SHA-256 mostrado no autentica la aplicación ni prueba aislamiento. setPassInput, isUnlocked y handleUnlock están sin uso según comprobación adicional de tipos; el flujo no exige una clave propia.

## XSS, CSRF, CORS, SSRF y validación

- No se encontraron dangerouslySetInnerHTML, eval, Function constructor de producto, shell exec/spawn o renderizado HTML de mensajes. Gmail muestra el cuerpo como texto React. Esto reduce sinks obvios; no es prueba de inmunidad a XSS en dependencias o navegador. [src/components/GmailModal.tsx:433](https://github.com/the-VanCartier-Authority/VVC-LIAM-CORE/blob/2ffadf44c2c09bbc8dcde47046ee7d5c08a039f7/src/components/GmailModal.tsx#L433).
- No hay política CORS explícita ni wildcard configurado en Express. Los defaults del navegador restringen lectura cross-origin; **no** debe afirmarse que se permite CORS abierto. No hay auth cookie de backend ni token CSRF: el problema primario es acceso anónimo, no un CSRF explotado demostrado.
- No se aplican CSP, Helmet, límites de usuario o validación de origen en código servidor. index.html carga scripts Google y fuentes externas. Una XSS del mismo origen expondría claves locales; no se explotó XSS ni se comprobó CSP del proxy de producción. [index.html:12](https://github.com/the-VanCartier-Authority/VVC-LIAM-CORE/blob/2ffadf44c2c09bbc8dcde47046ee7d5c08a039f7/index.html#L12), [index.html:97](https://github.com/the-VanCartier-Authority/VVC-LIAM-CORE/blob/2ffadf44c2c09bbc8dcde47046ee7d5c08a039f7/index.html#L97), [server.ts:19](https://github.com/the-VanCartier-Authority/VVC-LIAM-CORE/blob/2ffadf44c2c09bbc8dcde47046ee7d5c08a039f7/server.ts#L19).
- Custom/NVIDIA/test admiten URLs arbitrarias; no hay filtrado de redes privadas, redirecciones o tamaño de respuesta. fetch aborta algunos encabezados, pero no hay límite independiente de tiempo/tamaño para lectura de cuerpo. SSRF sí fue demostrada hacia mock local.
- Fechas, tiempos, prioridades, agentId, injectedSkills, temperaturas, max_tokens, delayMs y estructura de messages no tienen esquemas completos. TypeScript no valida JSON remoto. Se observó forcePriority INVALID aceptado.
